# 审核与安全发布流程

## 1. 内容简报

开始写之前确认：

- 项目和目标平台
- 目标受众和真实问题
- 内容目标：信任、教育、开发记录、演示、招募或转化
- 核心事实与证据
- 当前产品阶段和可执行 CTA
- 素材来源和 AI 参与
- 是否有商业合作或利益关系

## 2. 发布包结构

使用 `assets/publish-package-template.md`。最终包至少包含：

- 发布账号/平台
- 标题、正文、封面、素材顺序
- 标签/话题、定位、可见范围、计划时间
- CTA
- AI、商业、数据和素材声明
- 事实证据索引
- 审核结果和待确认项

素材必须按顺序编号，避免用户确认 A 顺序后实际上传 B 顺序。

### 视频封面生产门

视频笔记不得默认把首帧、旧版截帧或平台自动推荐图直接当最终封面。发布包进入确认前应：

1. 单独定义封面唯一主张，确保与标题、正文和视频核心命题一致；
2. 优先使用真实产品证据、已确认品牌资产和可编辑排版，不为“好看”虚构产品页面、用户结果或角色动作；
3. 检查完整目标比例、移动端小尺寸预览，以及平台可能使用的方形裁切。平台裁切锚点未核实时，至少同时生成顶部、中央、底部三种裁切模型；将主标题、核心视觉和必要身份信息放进这些模型的共同安全区；
4. 记录最终封面的文件、版本、来源、AI 参与、裁切预览和实际 SHA-256；旧封面保留为历史候选但明确不使用；
5. 上传页若默认截取首帧或推荐其他封面，必须主动替换并核对预览；未实际替换不得声称封面已设置成功。

**生成 QA 预览不等于通过 QA。** 必须逐张检查文字是否截断、缩略图是否可读、主体是否完整、信息是否互相遮挡，以及是否出现三个以上竞争中心。任一关键模型切掉主标题、核心证明或导致语义残缺，结论应标为失败并返回构图阶段；不得仅因文件已生成就写“已通过”。平台已提供实际预览后，以实际预览替代假设模型重新确认。

封面新增、替换、裁切位置或图内主文案变化属于素材实质变化，会使此前发布确认失效；展示新封面和差异后重新取得确认。

## 3. 审核报告

使用 `assets/compliance-report-template.md`。

审核结论只能是：

- 可发布：没有 P0/P1，仍列 P2 和平台不确定性
- 修改后发布：存在 P1，无 P0 或 P0 已解决
- 不发布：存在未解决 P0

每次改稿后只复用仍然成立的证据；重新检查被修改的语句、CTA、声明和素材。

## 4. 两阶段确认

### 阶段 A — 可逆准备

允许：

- 搜索和读取公开信息
- 生成、改写、排版和导出素材
- 打开平台页面、观察字段和限制
- 在本地准备上传顺序

在这个阶段向用户展示完整发布包，明确：

- 即将操作哪个账号
- 哪些内容将公开
- 是否选择 AI/商业等声明
- 是否发布、定时发布或仅保存草稿
- 尚存哪些 P2 风险

### 阶段 B — 外部写操作

确认后可以辅助填写和上传，但在最终按钮前做页面复核：

1. 账号正确
2. 标题与最终包一致
3. 正文与最终包一致
4. 素材数量与顺序一致，视频封面为已确认的独立版本而非默认首帧
5. 标签、定位、可见范围、时间一致。对小红书等带话题联想/选择器的平台，**正文里出现 `#xxx` 字符串不等于平台话题已选中**：逐个通过“话题”控件或输入联想选择候选，并核验编辑器中已形成平台可识别的话题实体/高亮样式；若只有普通文本，判定为未设置成功，不得进入发布
6. AI/商业等声明已正确选择
7. 页面没有新风险提示

如果平台不支持保存草稿，不要把“填写”当作无副作用操作；提前说明。

## 5. 确认有效性

有效确认必须针对可识别版本，例如“确认发布上面这版，3 张图，含 AI 声明”。

以下不视为长期授权：

- “以后你都直接发”
- “按老规矩”但本次内容未展示
- 对标题的确认被误当作对正文和素材的确认
- 几天前对旧版本的确认

内容实质变化时，展示差异：

```text
变更后需重新确认：
- 标题：A → B
- 第 2 张图：真实截图 → AI 概念图
- CTA：关注后续 → 立即下载
- 声明：新增“笔记含 AI 合成内容”
```

## 6. 评论与私信

评论、私信也是公开或定向外部沟通：

- 先引用要回复的上下文
- 生成候选回复
- 检查产品事实、隐私、承诺和冲突升级风险
- 展示最终回复和目标对象
- 用户确认后才发送

可以批量生成候选回复，但默认逐条展示、逐条确认、逐条发送。仅当用户明确要求批量执行时，必须完整列出固定批次内每个目标对象和每条最终文本，并取得针对该固定清单的一次性确认；发送中不得自动改写、追加目标或套模板扩量。出现新回复、敏感信息、页面提示或上下文变化时立即停止并重新确认。小红书不执行连续无人值守批量发送。

## 7. 失败处理

- 登录失效：停止，等待用户登录；不索取密码或导出 Cookie。
- 页面字段变化：重新观察，不依赖过期引用；无法确认规则时保守停在草稿。
- 上传失败：保留本地素材和错误证据，不重复点击造成重复发布。
- 发布后页面未确认成功：检查公开主页/内容列表，不凭按钮反馈声称成功。
- 话题只显示为普通 `#文本`、未出现候选选中状态或平台话题实体：视为填写失败；发布前重新选择并复核。若发布后由用户手动修正，记录修正时间和事实，不把原先普通文本误记为已成功设置的话题。
- 平台拦截：记录原始提示，不尝试绕过；回到审核阶段。

## 8. 操作记录

记录：

- 日期时间与时区
- 平台/账号
- 发布包版本或文件路径
- 审核最高风险
- 声明选项
- 用户确认原意
- 执行结果、公开 URL 或失败提示

不记录登录凭据或不必要个人数据。
