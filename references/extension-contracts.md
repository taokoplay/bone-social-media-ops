# 后续能力扩展契约

## 原则

V1 只定义接口和安全边界，不代表已经具备所有平台 API 或后台抓取能力。优先使用平台官方接口、创作者后台合法导出或用户授权数据。网页读取只允许在当前会话由用户人工触发、低频执行，并服从平台规则；Automation 只能处理官方许可接口、合法公开数据源或已由用户授权落地的静态数据。

## 1. 同品类调研与学习

### 输入

- 平台、品类和目标用户
- 关键词、账号样本或内容 URL
- 时间范围和样本上限
- 要回答的问题：选题、结构、用户痛点、评论问题、素材形式等

### 采集字段

- 内容 URL/内容 ID
- 作者公开名/账号 ID（仅必要字段）
- 发布时间和抓取时间
- 标题、正文摘要、公开标签
- 公开可见指标及平台口径
- 样本选择方式

### 输出

- 样本范围和局限
- 高频问题、内容支柱、表达结构、证据方式
- 可借鉴机制与不可复制的个人表达
- 候选选题和最小验证实验
- 不推断平台算法，不承诺“爆款公式”

### 边界

- 对小红书，不得由 Automation 或无人值守浏览器自动进入站内搜索、翻页、打开笔记/评论或模拟浏览；站内网页调研只能在当前会话由用户人工触发并低频进行
- 周期任务只能处理平台官方许可接口、合法公开数据源、用户人工提供/导出的样本或已授权落地的数据
- 不绕过登录、验证码、访问控制或反自动化机制
- 不高频翻页或批量抓取私人/受限数据
- 不复制原文、图片或个人故事做洗稿
- 作者公开信息只用于分析，不做骚扰、导流或画像拼接

## 2. 自有文章数据分析

### 适用数据

仅限用户自有账号、团队账号或明确授权账号。

### 推荐数据模型

```text
platform
account_id
content_id
published_at
snapshot_at
content_type
topic_pillar
experiment_tag
impressions_or_views
reads_or_plays
likes
favorites
comments
shares
follows_attributed
profile_visits
source_and_metric_definition
```

平台没有的指标留空，不用其他指标冒充。保存时间序列快照，不覆盖历史值。

### 分析输出

- 绝对值与标准化率（分母明确）
- 同账号、相近生命周期内容比较
- 内容支柱、形式、发布时间和 CTA 的相关性
- 样本量、不确定性和异常值
- 明确区分零、低量、数据缺失、后台延迟和平台限制提示
- 下一轮可验证实验，而不是事后故事

账号冷启动或低流量诊断同时读取 `cold-start-and-account-analysis.md`。发布不足 24 小时、数据看板尚未开放或样本仅个位数时，不计算并过度解释互动率，也不下“限流”结论。

### 自动化适配

适合用 Automation 做定期只读快照与报告，创建前明确：

- 数据来源与登录/授权方式
- 调度频率和平台访问限制
- 去重键、历史存储位置
- 失败处理和连续失败暂停
- 不执行任何发布或互动

## 3. 自有评论读取与分析

### 输入与采集

- 自有内容 ID/URL
- 时间范围、是否只看新增评论
- 评论 ID、发布时间、文本、父评论、公开互动数
- 昵称仅在回复需要时短期保留；报告默认匿名化

### 分析维度

- 问题、需求、异议、赞许、困惑、Bug 线索
- 情绪只作辅助，不把讽刺/方言判定当事实
- 是否需要事实核验、客服处理、风险升级或公开回复
- 高频主题和代表性匿名原句

### 候选回复

可以生成：

- 信息型回复
- 澄清型回复
- 感谢与追问
- 转客服/隐私渠道建议
- 不建议回复及理由

但不得自动发送。涉及账号、订单、车牌、手机号、定位等信息时，避免在公开评论继续追问敏感数据。

## 4. 自动化禁止项

无论是否有 Automation：

- 不无人值守发布笔记/视频
- 不自动评论、私信、群聊、关注或点赞
- 不模拟真人浏览和互动以操控平台指标
- 不绕过验证码、频控、登录或平台声明
- 不删除 AI 标识或伪造原创/用户关系

## 5. 新平台规则包规范

新增 `references/<platform>.md` 前必须包含：

- 平台名称、版本、核验日期和适用范围
- 官方来源 URL/内容 ID/界面路径
- 账号身份和内容声明
- 发布、导流、互动和自动化边界
- 特定内容类别风险
- 已确认规则与经验观察分区
- 不适用于该平台的其他平台规则
- 至少 3 个平台专项 eval

未完成这些字段，不把该平台列为正式支持。
