# 自媒体表现数据治理

## 目标

把发布后数据变成可追溯、可比较、可自动分析的运营证据，而不是一张不断覆盖的结果表。适用于自有账号的数据补录、复盘、低流量诊断、内容实验和合法自动化分析。

本文件定义运营语义和安全边界；若数据保存在 Obsidian，由 Obsidian Skill 负责 frontmatter、Dataview、迁移和展示实现。具体项目的字段名、平台窗口和专有业务指标应在项目契约中实例化，不写回公共 Skill。

## 唯一事实源

1. 每期内容包是该期内容、发布事实和表现数据的唯一事实源。
2. 汇总页、图表和日报只读取源记录，不手工复制第二份正文或指标。
3. 发布结果写入发布记录；历史指标追加到数据复盘；汇总脚本不得反向制造或覆盖事实。
4. 目录改名、延期或改题不得改变内容主键。

## 稳定内容主键

为每个内容包建立稳定 `issue_id`，推荐形式：

```yaml
issue_id: "{平台代码}-{年份}-{三位序号}"
```

约束：

- 在项目或账号范围内唯一；
- 创建后不得因延期、改题或目录重命名而变化；
- 内部主键与平台内容 ID 分开；
- 旧 `issue` 等字段只兼容读取，新内容统一写 `issue_id`；
- 通用 Skill 不写死具体项目 ID。

## 内容状态

推荐主状态流：

```text
idea → drafting → reviewing → approved → published → reviewing-data → archived
```

辅助状态：

- `deferred`：暂停排期但保留内容包；恢复时回到暂停前合理阶段。
- `cancelled`：明确取消但保留历史，不删除事实记录。

规则：

- `approved` 只授权当前固定版本；内容实质变化后退回 `reviewing`。
- `published` 必须有平台内容 ID、公开 URL 或其他可验证发布结果。
- 未知状态必须报数据质量问题，不静默归入默认状态。

## 指标快照

每次采集追加一条快照，不覆盖历史值。通用快照至少包含：

```text
快照时间、生命周期、曝光、阅读/观看、点击率、点赞、收藏、评论、分享、主页访问、归因关注、数据来源、备注
```

平台没有的字段保持空值；项目可以增加平台字段，但不要改变通用字段语义。

### 缺失值

- 未知、平台未提供、暂不可得统一视为 `null`，展示为 `—`。
- 只有平台明确显示 0 时才记录数值 `0`。
- 阅读/观看不冒充曝光。
- 账号净增粉不冒充单篇归因关注。
- 推断值、估算值和第三方猜测不得写入事实字段。
- 异常平台口径保留原始值和说明，但标记是否可用于结论。

### 数据来源

每条真实快照应能追溯到：

- 平台官方许可接口；
- 创作者后台；
- 用户授权导出；
- 人工核验后落地的数据。

自动任务只分析已合法落地的数据，不自动登录、翻页、抓取或模拟浏览平台页面，也不覆盖人工快照。

## 生命周期比较

推荐默认窗口：

```text
initial、2h、24h、3-7d、custom
```

平台或项目可调整窗口，但必须在项目契约中说明。

- 内容效果优先在相同生命周期比较。
- 不同生命周期的最新快照只能称为“已知规模”，不能称为效果排名或胜负。
- 缺少分母时不计算点击率、互动率或转化率。
- 发布不足 24 小时、样本为个位数或后台延迟时只描述事实。
- 数据完整度和缺失字段应与表现指标同时展示。

## 通用指标与专题指标

保持通用指标稳定。报名、线索、预约、试用、下载、成交等活动专有指标应使用扩展快照或独立表，不为了一篇活动反复修改通用指标契约。

专题指标仍需：

- 与同一内容主键关联；
- 记录快照时间与来源；
- 区分未知和 0；
- 不与通用内容指标混算。

## 数据质量级别

### 错误

影响可靠统计，应在分析前解决或明确阻断：

- 主键缺失或重复；
- 状态未知；
- 已发布但无可验证发布结果；
- 快照结构无法识别；
- 指标出现负数或明显类型错误。

### 警告

允许展示原始事实，但降低结论置信度：

- 使用旧格式；
- 生命周期或来源缺失；
- 关键字段未知；
- 快照时间不可解析或重复。

### 提示

不是数据错误，但限制解释：

- 发布不足 24 小时；
- 样本为个位数；
- 不同生命周期不能直接比较；
- 平台口径异常或延迟。

不得通过补 0、猜测或删除异常记录来消除质量问题。

## 内容分析变量

只保存表现指标不足以解释文章为什么有效或无效。每个内容包应结构化记录与结果相关的主要变量，推荐字段：

```yaml
content_format: "{图文/视频及页数或时长}"
topic_pillar: "{长期主题支柱}"
title_promise: "{标题向用户承诺解决什么}"
cover_promise: "{封面在小尺寸下传达的对象、场景和收益}"
content_structure: "{Hook → 论证/步骤 → 结果/CTA}"
primary_keyword: "{主要搜索表达}"
cta: "{正文唯一主要行动}"
experiment_variable: "{本篇相对对照只改变什么}"
target_signals: "{用于判断的主次指标}"
```

字段表达分析意图，不要求所有平台使用完全相同名称。具体值属于项目事实，不写进公共 Skill。

## 分析师决策链

运营看板或完整复盘按以下顺序回答问题：

```text
决策摘要 → 数据健康 → 表现趋势 → 同生命周期对照 → 文章拆解 → 漏斗诊断 → 行动与实验
```

1. **决策摘要**：已知什么、不能判断什么、当前最高优先诊断和当前决策。
2. **数据健康**：快照是否齐全、哪些窗口可比、还需补什么、是否有口径异常。
3. **表现趋势**：每篇随生命周期如何积累；单点只显示点，不伪造曲线。
4. **同生命周期对照**：只有相同窗口、单位和分母的数据才进入效果比较。
5. **文章拆解**：将标题、封面、首屏/前几秒、内容结构、关键词、CTA 和唯一变量与数据反馈放在一起。
6. **漏斗诊断**：定位最早有真实分母的薄弱环节，不跨过未知环节猜结论。
7. **行动与实验**：明确补数据、下一内容、只改什么、不同时改什么、观察窗口和停止条件。

## 文章级判断结构

每篇文章至少输出：

- **可确认**：直接受现有数据支持的事实与可定位环节。
- **不可确认**：缺失分母、缺失生命周期、样本不足或无法归因的部分。
- **主要假设**：最多 1–3 个可验证解释，不冒充因果或平台算法。
- **建议动作**：对应一个明确变量；数据不足时优先补录，而不是根据空值改内容。

不要从“点击率低”直接跳到“标题有问题”。先检查标题承诺、封面承诺、首屏兑现是否一致，再将某一项设为下一轮单变量。

## 漏斗诊断三段式

每篇漏斗卡或复盘结论必须包含：

1. **诊断层级**：发布状态、有效分发、曝光到打开、打开到停留、互动、主页承接或关注转化。
2. **证据限制**：数据窗口、分母、缺失字段、样本和平台口径。
3. **建议动作**：只针对当前最早可见瓶颈；分母缺失时动作是补数据，不是修改内容。

## 行动闭环

分析交付不能停在图表，至少列出：

- **待补数据**：内容、生命周期、字段和预期补录时间。
- **下一内容**：当前实验对象或选题。
- **本轮只改**：唯一主要变量。
- **本轮不同时改**：为保证归因而保持不变的形式、页数、CTA 或包装层级。
- **观察窗口**：早期状态、首轮比较和长尾窗口。
- **停止/调整条件**：多少次可比实验、什么证据或成本触发停止。

实验计划应有唯一事实源；看板读取并展示，不在多个脚本或页面重复手写。

## 指标与图表优先级

- 能改变下一步行为的指标优先于装饰性指标。
- 数据健康和可比性优先于互动构成环图等辅助图表。
- 不同生命周期累计使用“已知规模”，不能命名为“内容表现排名”。
- 没有两个同生命周期样本时显示“不可比较”，不要强行排序。
- 资产、文件入口和素材数量属于辅助管理，不与核心分析模块同级。

## 运营分析输出

复盘时分开写：

1. **事实**：原始指标、来源、快照时间和平台状态。
2. **诊断**：当前最靠前的漏斗瓶颈及数据限制。
3. **假设**：可能解释，不冒充平台算法事实。
4. **下一实验**：每篇只改变一个主要变量。
5. **停止条件**：样本不足、成本过高或关键假设被否定时停止。

数据治理保证“能信”；增长分析决定“怎么用”；行动闭环确保分析真正改变下一步。三者不能混为一层。
