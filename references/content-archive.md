# 每期发文归档

## 目标

运行本 Skill 时，不只生成散落的文案。若项目已有 Obsidian 或运营资料库，应为每一期发文建立完整内容包，把策划、审核、实际素材、发布记录和复盘放在一起，后续可完整追溯“发了什么、为什么这样发、用了什么素材、结果如何”。

## 先搜索，再建目录

1. 读取项目已有运营、推广、自媒体、内容策划或平台目录。
2. 发现已有平台唯一目录时复用，不再建立“运营管理”“自媒体”“发文”等同义根目录。
3. 发现多个同义目录时不继续扩散；列出候选并建议合并，未确认前优先写入已有正式索引所指向的目录。
4. 检查自动任务或脚本是否硬编码旧路径；移动/重命名前同步评估。
5. Obsidian 外部移动文件不会自动修复双链，移动前全局搜索 `[[旧路径`，移动后同步更新引用并再次搜索残留。

## 推荐目录

在项目已有推广体系下建立：

```text
{项目运营根}/{平台}/
├── 00-总览.md
├── 发文归档规范.md
└── {YYYY-MM-DD}-{主题}/
    ├── 00-本期总览.md
    ├── 01-内容与发布包.md
    ├── 02-合规审核.md
    ├── 03-发布记录.md
    ├── 04-数据复盘.md
    └── 素材/
        ├── 00-素材清单.md
        └── {实际发布素材}
```

目录日期使用内容首次建立或原计划发布的自然日。不要把示例项目名写入公共 Skill。

## 同期资料必须内聚

- `00-本期总览.md`：期号、主题、受众、目标、状态、导航和发布 Gate
- `01-内容与发布包.md`：最终标题、正文、标签、CTA、声明、事实证据和素材顺序
- `02-合规审核.md`：P0/P1/P2、证据等级、审核日期、修订记录
- `03-发布记录.md`：账号、发布时间、平台内容 ID、公开 URL、用户确认和页面提示
- `04-数据复盘.md`：指标时间序列、评论洞察、事实/推断和下一轮实验
- `素材/00-素材清单.md`：文件、顺序、来源、授权、AI 参与和脱敏

跨期通用素材可以留在公共素材库，但当期清单必须链接到实际使用版本；需要长期可复现时，将最终使用的素材复制到当期 `素材/`。

## 日期与命名

- 文件夹使用 `{YYYY-MM-DD}-{简短主题}`，例如 `2026-08-28-产品共创招募`
- 同一天只有一篇时不加序号；同一天多篇时，从第二篇起使用 `2026-08-28-02-主题`、`2026-08-28-03-主题`
- 日期表示内容首次建立或原计划发布日；发布延期时不重复建立新目录，在 frontmatter 和发布记录中更新实际日期
- 新内容使用 `issue_id: {平台代码}-{年份}-{三位序号}` 作为稳定主键，创建后不因延期、改题或目录改名而变化；旧 `issue` 只兼容读取，不参与文件夹命名
- 素材使用 `{YYYY-MM-DD}-{同日序号可选}-{顺序}-{用途}-{版本}.{扩展名}`
- 平台发布后继续更新同一个内容包，不另建重复发布稿或复盘稿

## 状态

建议：

`idea → drafting → reviewing → approved → published → reviewing-data → archived`

辅助状态：`deferred` 表示暂停排期，`cancelled` 表示明确取消但保留历史；二者都不删除内容包。

- `approved` 只表示用户确认了当前固定版本；内容实质变化后退回 `reviewing`
- `published` 必须有平台内容 ID、公开 URL 或可验证发布结果
- 数据复盘保留每次快照，不覆盖历史数值
- 指标字段、缺失值、生命周期和质量校验按 `performance-data-governance.md` 执行

## 动态总览

平台 `00-总览.md` 使用 Dataview 按 `type: social-content-issue` 聚合每期 `00-本期总览.md`。跨期发布和复盘页面也只做动态索引，不重复保存正文。

推荐 frontmatter：

```yaml
type: social-content-issue
project: "{项目名}"
channel: "{平台}"
issue_id: "{平台代码}-{年份}-{三位序号}"
date: "YYYY-MM-DD"
campaign: "{主题}"
objective: "{目标}"
status: drafting
published_url: ""
updated: "YYYY-MM-DD"
```

## 每次运行的写回规则

- 开始：确定平台目录和日期；若同日已有内容包，从第二篇起追加两位序号；读取本期总览与已有内容
- 内容定稿：更新 `01-内容与发布包.md`
- 审核：更新 `02-合规审核.md`，不得用旧审核覆盖新版本
- 素材变更：更新清单和发布包，旧确认失效
- 视频封面：独立归档最终封面、移动端小尺寸预览和平台可能使用的方形/中央裁切预览；记录版本、来源、AI 参与与哈希，不用首帧或平台推荐图替代已确认封面
- 发布：更新 `03-发布记录.md` 和本期总览状态
- 数据/评论：追加时间快照与洞察到 `04-数据复盘.md`
- 同一天重复运行：更新同一期文件，不建立重复目录

## Obsidian 链接规则

- 本期各文件链接 `[[00-本期总览]]`
- 本期总览链接平台 `[[../00-总览]]`
- 项目档案、日报或其他材料优先链接本期总览或发布包
- 重命名后全局检查旧双链残留
- 不把登录凭据、Cookie、Token 或不必要评论个人信息写入内容包
