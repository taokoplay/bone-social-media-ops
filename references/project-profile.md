# 项目内容档案

## 为什么需要档案

公共 Skill 不知道某个产品已经上线什么、不能承诺什么、哪些素材有授权。项目档案把这些事实从通用规则中分离，避免为一个项目优化后污染所有项目。

使用 `assets/project-profile-template.md` 创建档案。优先放在用户指定位置或项目运营文档目录；不要写进 Skill 目录。

## 建档顺序

1. 读取产品官网、PRD、版本说明、真实界面和用户明确提供的信息。
2. 按来源把内容分为：已核验事实、团队决策、待验证假设、未知。
3. 对会变化的信息写截至日期和时区。
4. 为高频主张记录可回查的文件、URL 或后台位置。
5. 与用户确认真正会改变发布合规结论的缺口。

## 最小字段

### 项目身份

- 项目/产品名
- 一句话定义
- 发布主体与账号关系
- 目标用户
- 当前阶段和截至日期

### 能力状态

每项标记：

- `available`：当前真实可用
- `beta`：灰度/测试中，需说明限制
- `planned`：计划中，不得写成已实现
- `unsupported`：明确不支持
- `unknown`：缺少证据

### 数据与证据

- 指标名称、数值、单位
- 截至日期、范围、样本和统计口径
- 来源路径或 URL
- 是否允许公开

### 对外口径

- 必须使用的表达
- 禁止或需证据的表达
- 下载/购买/报名状态
- 客服、官网和 CTA 边界
- 品牌语气和身份

### 素材与权利

- 自有/授权/第三方/AI/未知
- 肖像、声音、音乐、字体、商标授权
- 真实截图与概念视觉说明
- 演示数据和脱敏规则

### AI 使用

- AI 用于调研、文字、图片、视频、声音还是虚拟角色
- 最终公开内容中 AI 参与程度
- 平台声明与正文披露口径
- 禁止的 AI 用法

## 读取优先级

项目事实冲突时：

1. 用户本轮明确更新且可验证的信息
2. 当前产品/版本一手材料
3. 已确认项目决策与长期记忆
4. 历史运营文档
5. 推断或第三方描述

发现冲突不要静默选择，标明冲突与影响。

## 更新原则

- 只更新本轮已验证的最小事实。
- 上线状态、价格、指标和规则要写日期。
- 不保存账号密码、Cookie、Token、手机号等凭据。
- 用户案例保留授权状态和脱敏版本，不存不必要个人信息。
- 计划变化不等于已实现，状态转换必须有证据。
