# IP 主导的社交内容模式

> 适用：小红书等公开内容使用持续出现的 App IP、品牌角色、吉祥物、人格化物件、陪伴形象或抽象 IP。
> 边界：本文件负责把已存在的 IP 正确转化为内容身份、叙事职责和发布约束；不负责从零设计角色、重建三视图或生产复杂动作资产。

## 1. 何时进入本模式

满足以下任一情况时进入 IP-led Content 模式：

- IP 作为标题、封面、正文或连续图文中的主要讲述者；
- 使用 IP 第一人称、角色口吻或持续人格经营账号；
- IP 用动作或状态解释真实产品功能、用户结果或关系价值；
- 内容属于固定角色连载、IP 开发日志或 App × IP 功能介绍；
- 新一期内容必须与既有角色身份、人格和视觉资产保持一致。

仅使用一次性插画、Emoji、普通贴纸、装饰性人物或无持续身份的视觉时，不进入本模式。不要为了“更有品牌感”强行把 IP 塞进所有内容。

## 2. 先锁定本期发言身份

每篇内容选择一个主要发言身份；辅助身份不得抢夺事实责任。

| 身份 | 适合内容 | 主要证据 | 主要风险 |
|---|---|---|---|
| 开发者本人 | 开发日志、迭代过程、取舍复盘 | 真实开发过程和当前产品 | 伪造经历、把团队行为包装成个人经历 |
| 品牌团队 | 功能介绍、版本更新、活动说明 | 项目档案、版本和正式口径 | 广告感过强、品牌承诺超过产品事实 |
| IP 第一人称 | IP 连载、陪伴内容、轻剧情 | 已确认人格、角色职责和可用资产 | 假装真人、虚构自主行为、替产品作无法兑现的承诺 |
| 用户视角 | 使用经验、问题场景、案例故事 | 真实授权案例或明确标记的合成示例 | 虚构用户、评价、病情、结果或隐私事实 |

规则：

- IP 第一人称是一种叙事包装，不会改变产品事实、行为主体或责任主体。
- 角色可以说“我陪你看看记录”，不能把系统没有执行的动作写成“我已经替你记录/提醒/诊断”。
- 用户视角没有真实授权案例时，改成“常见场景”“假设示例”或开发者观察，不伪造投稿、评论和聊天记录。
- 标题、正文、封面身份线索和账号资料应一致；故意制造“真人用户分享”错觉属于真实性风险。

## 3. 给 IP 一个真实内容职责

每次 IP 出现至少承担一个主要职责：

- **讲述者**：以稳定人格组织真实内容；
- **导游**：引导读者理解真实页面、步骤或证据；
- **执行者**：用动作表现一个产品动词，但不篡改真实交互主体；
- **反馈者**：表达 completed、waiting、empty、offline 等真实状态；
- **关系载体**：提供陪伴、安抚或庆祝，不制造依赖和情绪勒索；
- **品牌锚点**：维持系列识别，但不抢夺钩子与证据。

执行检查：

1. 用一句“IP 在本期负责……”写清职责；
2. 删除 IP 后若信息、叙事和理解完全不受影响，将其降为装饰，不为它牺牲真实证据或版面；
3. 一篇内容默认只给 IP 一个主职责，最多一个强耦合的辅助职责；
4. IP 的动作、台词、表情和页面状态必须指向同一个产品命题。

## 4. 人格、语气与责任边界

在内容简报中记录：人格锚点、允许语气、禁用语气、称呼方式、角色知道什么、不能声称什么。

### 允许

- 陪伴、解释、庆祝、轻度自嘲和具体观察；
- 承认限制、不确定和开发中的状态；
- 把复杂功能转成易懂比喻，同时保留真实说明；
- 对用户结果给予反馈，但不替用户或系统承担虚假动作。

### 禁止

- 羞辱、催促、卖惨、恐吓、健康焦虑或“你不做我就难过”；
- 把 missed、error、offline 等状态一律归咎用户；
- 冒充医生、药师、真人用户、客服或具有实际权限的自主 Agent；
- 声称已读取、记录、提醒、诊断、同步或保护数据，而产品事实不能证明；
- 为了角色感编造用户数量、疗效、投稿、评论、获奖、媒体评价或开发过程。

系统错误不能表现成用户做错。健康、医疗、药物相关内容中，IP 的可爱表达不能弱化必要限制，也不能把陪伴语言升级为医疗建议或效果承诺。

## 5. 图文和封面使用规则

同时执行 `xiaohongshu-visual-editorial.md`：

- 封面仍以钩子、身份/视角和证据线索为先；IP 不能同时替代三者；
- 品牌角色可作为身份线索或主要视觉焦点，但第 1–2 张应尽快出现真实截图、实拍或其他事实证据；
- 连续图文逐页写明 IP 职责，不让角色每页只换姿势重复卖萌；
- 使用已确认资产时优先排版、裁切和组合，不为每期无意义重生角色；
- 新生成的动作、表情、换装或多角度场景必须标记资产状态和来源，不把探索稿当正式身份事实源；
- 240px 缩略图下先检查主钩子，再检查 IP 是否仍可识别；角色细节不能挤压标题可读性；
- 真实 App UI 与角色包装分层呈现，不绘制近似 UI 冒充真实截图。

## 6. 何时调用 `bone-app-ip-design`

仅当本期内容出现下列生产缺口时组合使用 `bone-app-ip-design`：

- 从零创建或实质修改 IP 身份、结构、人格或核心识别机制；
- 新生成正式动作、表情、姿势、换装、背面/侧面或复杂场景角色图；
- IP 需要表达 completed、missed、loading、offline、error 等真实业务状态；
- 缺少当前 Canonical source、三视图或身份锚点，或现有衍生稿发生身份漂移；
- IP 资产还将进入 App、Icon、Widget、商店素材、动态表情或跨平台正式生产。

以下情况通常不必调用完整 App IP 流程：

- 使用已有且已确认的透明角色资产进行封面排版；
- 只调整标题、正文、标签、CTA 或素材顺序；
- 一次性普通插画不承担持续 IP 身份；
- 仅判断小红书声明、权益和发布风险。

若专项 Skill 当前不可用或用户没有必要资产，不虚构“已完成身份锁”。继续输出内容草案，但把新角色资产、人格稳定性和正式发布状态标记为待确认或待工具执行。

## 7. AI、身份和真实性披露

AI 声明与账号身份判断以当前平台规则包 `xiaohongshu.md` 为准：

- 吉祥物头像或品牌 IP 不自动等于 AI 虚拟人账号；
- 若角色以类似真人身份持续自主发帖、评论、私信或建立关系，重新评估账号职业/身份披露；
- AI 生成或实质编辑的角色视觉、正文、声音和视频分别记录，不用“IP 是虚构的”规避 AI 声明；
- 明确区分真实 App 截图、AI 品牌包装、概念效果和演示数据；
- IP 背后由真实团队运营时，可以透明说明，不把人工审核包装成角色自主行动。

## 9. 发布前 IP 专项检查

在五层审核中追加以下检查，不另造一套风险等级：

- **事实层**：IP 台词是否改变功能、阶段、行为主体或责任主体；
- **平台层**：账号身份与 AI 内容声明是否匹配实际运营方式；
- **权益层**：角色、字体、服装、道具、声音和参考素材是否有权使用；
- **素材层**：Canonical/正式/探索资产是否区分，真实 UI 与 AI 包装是否分层；
- **运营层**：IP 是否有真实职责，角色口吻是否稳定，是否过度广告化、情绪勒索或遮蔽证据。

发布包应记录主要发言身份、IP 版本/资产来源、本期职责、新生成资产状态和 AI 声明。任何 IP 资产、角色身份或叙事主体的实质变化，都视为发布包发生实质变化，需要重新审核并让用户重新确认。
