# 自媒体运营计划与 OKR 控制环

> 方法版本：1.0.0
> 建立日期：2026-09-02（GMT+8）
> 适用范围：账号持续运营、内容生产、复盘、起号、排期与增长实验
> 证据边界：本文件定义项目运营控制面，不提供平台保证值，也不把第三方经验写成算法规则。

## 1. 每次运行先做轻量控制面检查

每次本 Skill 触发时，在执行当前任务前先恢复运营控制面；只读取必要索引和当前有效文件，不全量扫描资料库：

1. 确认项目、平台、账号和当前任务；
2. 在用户指定位置、项目运营目录、Context 或已有索引中查找当前有效的运营计划、OKR/阶段指标、内容排期和最近复盘；
3. 核对计划的有效期、状态、数据截至时间、下一动作和阻塞项；
4. 将本轮请求关联到某个目标、关键结果、实验或必要运营维护；无法关联时标为临时任务并说明是否应纳入计划；
5. 再执行创作、审核、发布、数据补录或分析。

“查看”是轻量恢复，不等于每次重做账号、品类和竞品研究。存在可用计划时，只读取计划、最近数据和与本轮相关的内容包。

### 快速路径

以下任务仍执行控制面检查，但不得因补规划而延误：

- 紧急合规审核、侵权/隐私修复或平台异常处理；
- 已完成两阶段确认、仅等待最终页面复核的发布操作；
- 用户明确限定为一个小修改，且该修改不改变目标或实验变量。

这类任务先完成安全关键动作，再把计划缺口记为待补；不能在旧确认已经失效时借“快速路径”继续发布。

## 2. 什么算“当前有效计划”

至少包含：

- 项目、平台、账号与计划周期；
- 账号阶段和截至日期；
- 一个清晰的目标或北极星验证链；
- 可衡量的关键结果，含指标定义、基线、目标/方向、截止时间和数据来源；
- 内容支柱、目标人群和当前假设；
- 近期任务或实验，含负责人/执行主体、顺序、观察窗口和停止条件；
- 最近复盘时间、真实数据截至时间、阻塞与下一动作。

只有内容日历而没有目标和复盘机制，不算完整运营计划；只有宏观 OKR 而没有可执行任务，也不算完整。

若发现多份计划：优先使用用户明确指定、状态为 active、有效期覆盖当前日期且被项目总览链接的文件。冲突不能静默合并，应列出冲突字段和影响，选择临时事实源或向用户确认。

## 3. 没有计划时：先分析，再建最小可执行计划

### 3.1 恢复已有证据

按最小必要范围读取：

- **项目分析**：产品阶段、真实能力、目标用户、商业目标、可用 CTA、品牌和资源约束；
- **账号分析**：定位、历史内容、受众、内容形式、账号状态、后台可得指标及同生命周期基线；
- **品类分析**：用户任务、需求频率、搜索表达、季节性、风险与内容供给特征；
- **竞品/替代方案分析**：直接账号、间接内容替代、常见承诺、证据形态、评论问题和差异机会。

复用近期研究。只有证据缺失、已过期或会改变目标时才新增研究。站内竞品研究仍遵守低频只读、合法来源和不自动模拟浏览的边界；产品市场竞争分析可组合 `competitor-analysis`，不能把营销账号样本冒充整个市场结论。

### 3.2 信息不足时的处理

- 能从项目事实源验证的，不重复询问用户；
- 缺口不影响首轮方案时，标为未知并建立“补证据”任务；
- 缺口会改变商业目标、受众、预算、公开承诺或外部动作时，只问少量高价值问题；
- 不因为缺少全量竞品数据而停摆，可先建立 7–14 天最小实验计划，但必须降低置信度。

### 3.3 计划结构

使用 `assets/operating-plan-and-okr-template.md`，至少形成：

1. 当前事实与证据截至时间；
2. 北极星验证链；
3. 1–3 个阶段目标；
4. 每个目标 2–4 个关键结果；
5. 内容支柱与受众假设；
6. 近期任务/实验及优先级；
7. 数据采集窗口与责任边界；
8. 保持、调整和停止 Gate；
9. 风险、阻塞和下一次复盘。

关键结果同时覆盖过程、数据完整度、内容/受众信号和业务承接。不要只写粉丝、曝光等结果数字，也不要只列“发几篇”的活动量。

## 4. 指标设计规则

每个指标写清：

```text
指标名、业务含义、公式/平台原口径、基线、目标或方向、截止时间、数据来源、归因等级、缺失值规则
```

约束：

- 优先采用平台官方字段并保留原名；
- 未知、未提供和暂不可得写 `—`/`null`，不补 0；
- 同生命周期、同分母、相近受众和形式才进入效果比较；
- 目标数字分为保守底线、项目目标区间和挑战目标；
- 每个具体数字标注制定日期和依据；没有官方证据时不得称为平台标准；
- 粉丝、曝光是滞后结果，必须搭配收藏、具体评论、主页访问、归因关注或业务信号；
- 无内容级归因时只能写同期相关，不把账号净增、下载变化或成交强行归因给单篇内容。

## 5. 有计划时：对比真实数据并滚动优化

### 5.1 先检查数据健康

读取计划、最近一次复盘和已人工核验落地的数据。按 `performance-data-governance.md` 检查：

- 快照窗口和字段是否齐全；
- 未知与 0 是否分开；
- 是否存在平台延迟、口径变化或异常值；
- 哪些内容可以同生命周期比较；
- 计划指标是否仍可测量。

缺少关键数据时，下一动作优先是补录；不根据空值修改内容策略。

### 5.2 输出“计划—实际—判断—动作”

每次实质性运营复盘至少包含：

| 目标/KR | 截至当前计划 | 真实值与来源 | 进度/差距 | 证据限制 | 后续动作 |
|---|---|---|---|---|---|

状态建议：

- `on-track`：按当前节奏有合理证据可达；
- `at-risk`：进度或前置信号不足，需要局部调整；
- `blocked`：缺数据、权限、素材、产品能力或外部依赖；
- `achieved`：有可核验证据完成；
- `invalidated`：目标或假设已被证据否定；
- `unknown`：数据不足，不能判断。

不得只按时间比例机械计算进度。结果指标尚未出现时，应检查对应前置信号和实验完成度。

### 5.3 更新任务，而不是只写分析

根据最早可见瓶颈更新后续任务：

1. 完成项按事实标记完成；
2. 未完成但仍有效的任务保留，不因延期删除；
3. 无效或被证据否定的任务标记取消/替换，并记录理由；
4. 新任务必须关联目标/KR、明确交付物、优先级、依赖、观察窗口和完成定义；
5. 下一篇内容坚持单变量实验，写清“本轮只改”和“本轮不同时改”；
6. 外部发布、评论、私信仍执行两阶段确认，不因计划已批准而获得长期授权。

若运行环境提供 Todo/日程能力：明确且用户认可的后续行动可同步为 Todo；有明确开始时间的安排才进入日程。计划文档是策略事实源，Todo 是执行投影，二者不得各自维护冲突版本。

## 6. 优化层级

按证据从小到大调整，避免一次低量导致策略漂移：

1. 补数据或修正口径；
2. 调整单篇标题、封面、首屏、模板或 CTA 中一个变量；
3. 调整某个内容母题的形式或优先级；
4. 调整内容组合和节奏；
5. 只有达到预设停止条件后，才调整目标人群、定位或整体策略。

计划变更必须记录：变更日期、原计划、真实证据、变更理由、影响的 KR/任务和下一验证窗口。不得用新计划覆盖旧判断，需保留变更历史。

## 7. 每次运行的最小状态摘要

即使本轮主要任务是创作或审核，也应在内部完成检查，并在有用时简短报告：

```markdown
## 运营控制面
- 当前计划：存在 / 缺失 / 过期 / 冲突
- 当前阶段与目标：
- 数据截至：
- 本轮关联：目标 / KR / 实验 / 临时任务
- 进度判断：on-track / at-risk / blocked / achieved / invalidated / unknown
- 本轮完成：
- 下一动作：
```

若计划存在且本轮没有新数据或策略变化，不制造重复复盘、不重写计划，只说明“沿用当前计划”。

## 8. 自动化边界

持续跟进可以由 Automation 定期分析**已合法落地**的数据和计划文件，并生成进度、缺口与候选任务；仍不得自动进入平台网页、发布、评论、私信、点赞、关注、拉群或模拟浏览。

自动任务只能提出或更新内部建议。涉及公开动作、付费、权限变化或外部来源写回，继续遵守用户确认和对应工具规则。
