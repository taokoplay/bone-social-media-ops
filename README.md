# Bone Social Media Ops

一个面向产品、品牌和项目团队的通用自媒体运营 Agent Skill。它将运营计划与 OKR、内容策划、事实核验、平台规则、素材权益、发布门禁、账号冷启动和数据复盘组织成可复核的工作流。

当前正式支持 **小红书**；其他平台只能先执行通用事实与权益审核，核验该平台官方规则并建立规则包后，才能声称完整支持。

## 能做什么

- 建立项目内容档案和稳定的账号对外口径
- 每次运行轻量检查当前运营计划、OKR、排期与最近复盘
- 没有计划时，基于项目、账号、品类和竞品/替代方案建立指标与任务计划
- 已有计划时，对照真实数据跟进 KR，滚动优化后续任务
- 生成标题、正文、封面文案、素材顺序、标签、CTA 和完整发布包
- 执行事实、平台、法律与权益、素材、运营五层审核
- 处理小红书 AI 内容声明、账号身份和自动化边界
- 分析新账号、低流量和冷启动状态，设计 7 / 14 / 30 天目标与内容实验
- 按 2h、24h、3–7d 生命周期保存自有内容指标快照
- 辅助填写发布页面，并在最终公开操作前保留人工确认门禁
- 为同品类调研、自有评论分析和合法只读自动化定义安全接口
- 将每篇内容的策划、审核、素材、发布记录和复盘归档到同一内容包

## 不做什么

- 不保证过审、流量或爆款
- 不把网络“敏感词表”“养号教程”或算法传言包装成平台官方规则
- 不无人值守发布、评论、私信、关注、点赞或模拟真人浏览
- 不刷量、互赞、操控账号矩阵或绕过验证码、风控和 AI 标识
- 不虚构产品功能、用户案例、数据、评价、新闻或效果
- 不将小红书规则机械套用到抖音、视频号等其他平台

## 安装

### 安装到通用 Agent Skills 目录

```bash
git clone https://github.com/taokoplay/bone-social-media-ops.git \
  ~/.agents/skills/bone-social-media-ops
```

如果你的 Agent 使用其他 Skills 根目录，将仓库克隆或复制到该目录即可。目录中应直接包含 `SKILL.md`：

```text
<skills-root>/bone-social-media-ops/SKILL.md
```

### 更新

```bash
git -C ~/.agents/skills/bone-social-media-ops pull --ff-only
```

### 验证

仓库提供无第三方 Python 依赖的结构与安全不变量验证：

```bash
python3 scripts/validate_skill.py
```

成功时会输出：

```text
VALIDATION PASSED
```

## 如何使用

安装后，直接向支持 Agent Skills 的助手描述自媒体任务。以下请求应该触发本 Skill。

Skill 每次运行都会先做轻量运营控制面检查：确认项目当前是否有有效计划、OKR/阶段指标、排期和最近复盘。已有计划只做必要的增量跟进，不会每次重新调研；没有计划时才补做最小必要分析并建立计划。紧急合规、隐私修复和已确认发布前复核走快速路径，不会被长篇规划阻断。

### 1. 建立项目档案和账号定位

```text
我们在做一个还没上架的宠物健康记录 App。
请建立小红书项目档案，梳理账号定位、产品事实、不能说的承诺和首批内容支柱。
```

Skill 会优先确认：

- 产品是什么、面向谁、当前阶段
- 已上线、测试中、计划中和未支持的能力
- 可证明的数据、案例和来源日期
- AI 参与、素材权利和隐私边界
- 当前 CTA 是否真实可用

未知信息会标为未知，不会为了补全内容而虚构。

### 2. 建立或跟进运营计划与 OKR

```text
先检查这个账号有没有当前有效的运营计划。如果没有，结合项目、账号、品类和竞品分析建立30天目标；如果已有计划，就对比真实数据，更新进度并安排下一周任务。
```

计划至少包含：

- 当前事实、数据截至时间与证据限制
- 北极星验证链与1–3个阶段目标
- 覆盖过程、数据完整度、受众价值和业务承接的关键结果
- 内容支柱、近期单变量实验和数据采集窗口
- 保持、局部调整和停止 Gate
- “计划—实际—判断—动作”进度表与计划变更记录

具体数字属于项目内部目标，不会写成平台保证或跨行业硬标准。计划是策略事实源；Todo 或日程只是执行投影，不能维护冲突版本。

### 3. 创建完整发布包

```text
给这个产品写一篇小红书共创招募笔记。
封面使用 AI 插画，正文包含两张真实 App 截图。
请输出完整发布包并完成发布前审核，但先不要发布。
```

默认交付包括：

- 推荐标题与备选标题
- 完整正文
- 封面文案和素材顺序
- 话题标签与唯一 CTA
- AI、商业关系和演示数据声明
- 五层审核结果与 P0/P1/P2 风险
- 最终仍需用户确认的项目

### 4. 审核已有内容

```text
审核这篇小红书笔记，重点检查产品事实、AI 声明、客户隐私、音乐授权和导流风险。
```

审核不是简单扫描词语，而是建立“主张—证据”关系。每个风险项会说明：

- 原文或素材位置
- 风险等级
- 判断理由与上下文
- 证据来源等级和日期
- 可直接执行的修订

### 5. 分析新号与低流量

```text
新账号第一篇发布 3 小时只有个位数观看，后台数据还没开放。
请判断是不是限流，并给我一个 14 天起号实验。
```

Skill 会先检查：

1. 发布、审核、可见性和账号状态
2. 数据权限、更新延迟和当前样本量
3. 曝光到打开
4. 打开到停留或完播
5. 收藏、评论和分享
6. 主页访问、关注和目标行动

发布不足、后台延迟或个位数样本不会被直接解释为限流。网络上的“固定流量池、首小时阈值、养号天数”只会作为待验证经验，不作为官方事实。

### 6. 辅助发布

```text
这是已审核的最终发布包。打开小红书创作平台，帮我填写标题、正文和话题；最终点击发布前停下来让我确认。
```

公开操作采用两阶段门禁：

1. **准备与审查**：展示完整标题、正文、素材、标签、声明、账号和动作，清零 P0/P1；
2. **执行**：获得当前版本明确确认后才填写或上传，最终按钮前再次核对。

标题、正文、CTA、素材、声明、账号、可见范围、时间或平台选项发生实质变化时，旧确认失效。

### 7. 发布后复盘

```text
这是我们自有账号最近 8 篇内容的后台导出。
请按 24 小时和 3–7 天生命周期对齐，分析内容支柱并设计下一轮实验。
```

Skill 会区分：

- 事实：后台数值、平台提示和真实评论
- 相关性：主题、形式或 CTA 与指标共同变化
- 假设：可能原因
- 实验：下一轮只改变的主要变量
- 停止条件：何时放弃该方向

不会把单篇高曝光事后包装成可照抄的“爆款公式”。

## 默认审核输出

```markdown
# [平台]内容合规审核

## 结论
- 发布建议：可发布 / 修改后发布 / 不发布
- 最高风险：P0 / P1 / P2 / 未发现明显风险
- 规则截至：YYYY-MM-DD

## 风险项
| 等级 | 证据片段/素材 | 判断与上下文 | 来源等级 | 修订 |
|---|---|---|---|---|

## 声明与设置
- AI 内容声明：
- 商业关系声明：
- 示例/脱敏数据：
- 其他平台选项：

## 最终发布包
- 标题：
- 正文：
- 素材顺序：
- 标签：
- CTA：

## 待确认
- [需要用户确认的具体事项]
```

## 风险等级

- **P0 阻断**：已知虚假事实、隐私或明显侵权、违法/危险行为、平台明确禁止的自动化、不可用 CTA 等；解决前不发布。
- **P1 必改**：证据不支持表达强度、关键声明缺失、标题与内容不一致、明确导流或权益风险等；修改后重新审核。
- **P2 提醒**：第三方经验、低置信度观察、轻度语义误解或运营节奏建议；说明不确定性后由用户权衡。

## 证据等级

- **A**：法律或监管官方原文
- **B**：平台官方规则、官方公告或当前官方界面
- **C**：自有账号或平台的稳定实操观察
- **D**：第三方教程、经验、词库或服务商资料

P0/P1 必须说明证据等级。没有官方证据的“据说会限流”不能升级为平台硬规则。

## 项目归档

如果项目使用 Obsidian 或其他运营资料库，每一期建议建立：

```text
YYYY-MM-DD-主题/
├── 00-本期总览.md
├── 01-内容与发布包.md
├── 02-合规审核.md
├── 03-发布记录.md
├── 04-数据复盘.md
└── 素材/
    └── 00-素材清单.md
```

同一期的文案、审核、素材、用户确认、发布结果和数据快照应放在一起，避免多个同义目录和过时静态索引。

## 维护平台规则

更新 `references/xiaohongshu.md` 时应同时记录：

- 官方来源 URL、内容 ID 或界面路径
- 核验日期和适用范围
- 平台明确要求、平台建议与实操观察的区别
- 变化点及受影响的 eval

第三方经验和真实运营数据只能先形成候选规则；升级为平台硬规则前必须找到 A/B 级证据。

## 贡献

欢迎提交 Issue 或 Pull Request。修改规则、发布门禁或自动化边界时，请同步补充相应行为评测，并运行：

```bash
python3 scripts/validate_skill.py
```

提交内容不应包含：

- 项目或客户专属事实
- 账号凭据、Cookie、Token 或个人信息
- 无法公开的素材和评论原文
- 未核验却被描述为官方规则的第三方经验
